# 쇼츠 구간 발굴 규칙

두 기존 파이프라인(수학쌤 ncs · 비블 bibl-shorts-automation)에서 실제로 반려·재작업을 부른 원인들을 규칙으로 만든 것이다. 규칙끼리 부딪히면 **맥락(혼자 봐도 말이 되는가)이 길이보다 먼저**다.

## 1. 재료 읽기
1. `projects/<p>/transcript.md` 를 처음부터 끝까지 읽는다. 표시: `▌` 카메라 컷 · `[얼굴없음]` 화면공유·자료 화면 가능성 · `~~버림~~` 환각 필터.
2. 경계 후보가 생기면 `./shorts.sh words <p> <t0> <t1>` 로 단어 시각표를 본다(`‖` = 0.3초 이상 쉼 = 자르기 좋은 자리). 전사 단어 시각은 이르게 찍히는 일이 잦아도 괜찮다 — build 가 소리 골짜기로 다시 맞춘다. **초를 반올림하지 말고 단어 시각 그대로** 쓴다: `in` = 첫 단어 start, `out` = 끝 단어 end(구간 판정은 단어 중점 기준이라 다음 짧은 말을 끌어오지 않는다).
   `▌` 카메라 컷은 편집된 클린본의 점프컷도 포함한다(구도가 바뀌는 곳). 엔진이 컷마다 조각을 나눠 따로 크롭하므로 구간이 컷을 넘어도 된다 — 다만 구간 **시작·끝**은 컷 직후·직전 1~3프레임에 걸리지 않게 문장 단위로.
3. 챕터 구조(예고 → 본론 1·2·3 → 정리)를 먼저 표로 분해하면 후보가 빨리 보인다.

## 2. 기승전결 게이트 (탈락 기준, 최우선)
후보마다 네 요소의 **시작 타임코드**를 적는다. 하나라도 못 적으면 후보가 아니다.
- 기(문제 제기·후킹) · 승(전개·근거) · 전(핵심·반전) · 결(결론·행동 지침)
- 문장 조각을 이어 붙여 완결성을 만들어내지 않는다. 기본 단위는 챕터 하나 통째(너무 길면 승 안의 반복·곁가지만 skip 제안).
- 실제 탈락 사례: 예고만 있는 인트로(결 없음) · 챕터 전환 문장 · **클린본에 없는 판서·자료를 "이거", "여기", "이쪽 쭉 넘어가서"로 가리키는 구간**(쓰려면 "자료 인서트(표·숫자 그래픽) 필요"로 표시하고 사용자와 합의).

## 3. 독립 영상 원칙
쇼츠는 따로따로 하루 간격으로 소비된다. 앞 내용·다른 편을 가리키는 말을 찾아 표시하고 가능하면 `skip` 으로 뺀다:
"아까 말했듯이", "앞에서", "첫 번째는/두 번째는"(챕터 서수), 시작의 "그리고/그래서", "선생님이 오늘 알려준 방법대로".
skip 은 단어 단위로 소리 골짜기에서 잘리고, build 가 **잘린 자리를 다시 전사해** 지운 말이 남았으면 다음 음절 경계로 옮긴다(`경계 보정 … 확인 권장` 로그 — ㄲ·ㄷ·ㄱ 같은 폐쇄음 앞의 짧은 무음은 단어 경계가 아니라서 생기는 일). 보정된 경계는 사람이 한 번 들어 본다. 빼면 문장이 깨지는 경우만 위험으로 두고 사용자에게 묻는다.

## 4. 화면·얼굴 확인
- `[얼굴없음]` 이 섞인 구간은 빼거나 경계를 문장 단위로 민다. 16:9 자료를 꼭 보여야 하면 `layout: "fit"`(가로 전체 + 흐린 배경) 제안.
- 인용 푸티지(다른 인물)·챕터 카드·상시 텍스트 그래픽은 얼굴 스팬으로 안 잡힌다 — 의심되면 `ffmpeg -ss <t> -i <원본> -frames:v 1` 로 프레임을 직접 본다.
- 두 사람이 나오는 샷은 `focus: "left"|"right"`(말하는 사람)를 지정한다.
- 카메라 컷(▌)은 엔진이 샷마다 크롭을 따로 잡고, 한 샷 안에서 화자가 움직이면 가상 카메라가 따라간다. 구간 끝이 컷 직후 1~3프레임에 걸리지 않게 문장 끝을 확인한다. 엔진 안전장치: 0.08초 미만 조각은 버리고, 구간 첫·끝의 0.35초 미만 조각(첫 음절이 앞 샷에서 시작된 경우 등)은 **소리는 두고 화면만 이웃 샷의 첫(끝) 프레임을 멈춰** 보여 준다 — 화면공유·다른 구도가 한순간 비치지 않는다.

## 5. 길이·점수·순서
- 길이: `brands/<b>.json clip` — 수학쌤 40~100초(이상 60~90) · 비블 30~75초(이상 40~60). 맥락 때문에 넘으면 길이를 명시하고 사용자가 결정.
- 4축 점수(각 1~5): 훅 잠재력 · 감정 밀도 · 실용 가치 · 논쟁성. **13점 이상만 후보**, 11~12 보류.
- 한 원본에서 주제가 겹치면 점수 높은 쪽만. 발행 순서는 주제가 번갈아 나오게 제안(본문 겹치는 편은 사흘 이상 띄움).

## 6. 리포트 `projects/<p>/candidates.md`
```markdown
# <원본> 쇼츠 후보 (<날짜>, 브랜드 <b>)
## 챕터 분해
| 구간 | 내용 | 비고 |
## 후보
### 1. <가제> — <시작>~<끝> (<길이>초) · 점수 <합>/20 (훅 a·감정 b·실용 c·논쟁 d)
- 기 <tc> "<첫 문장>" / 승 <tc> / 전 <tc> / 결 <tc> "<끝 문장>"
- 경계: 시작 단어 "…"(<초>) · 끝 단어 "…"(<초>) · skip: "아까 말했듯이"
- 위험: 지시어 · 얼굴없음 · 길이 초과 · 오인식 등 (없으면 '없음')
- 추천 제목 방향(1줄): …
## 제외한 구간과 이유
## 전사 확인 필요
| 시각 | 들린 대로 | 추정 | 확인 방법 |
## 추천 발행 순서
```

## 7. 고른 뒤
- 편마다 `./shorts.sh new <p> <id> --in <초> --out <초> [--skip "…"] --name <납품명>` 후 `short.json` 의 `brief`(message 한 문장·arc 네 시각·audience·mood)를 채운다.
- 컷확인 단계면 `./shorts.sh cut <p>/<id>` → `out/<id>_컷확인.mp4` 를 사용자에게. 사용자가 재구성하면 segments 만 고친다(예: 시작을 "냉정하게" 단어로).
- 확정 교정(교재명·용어)은 `brands/<b>.json corrections` 에 추가해 다음 편부터 자동 반영(추정 교정 금지).
